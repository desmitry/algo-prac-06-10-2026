# Практическая работа № 2. Сортировки за линейное время

Запуск:

```
javac *.java
java BucketSort
java RadixSort
java CountingSort
```

В каждом `main` прогоняются примеры из задания (ожидаемый результат сравнивается с полученным) и большой случайный массив, который сверяется с `Arrays.sort`.

## 1. Доли голосов — BucketSort

Значения от 0 до 1 и распределены по всему интервалу, корзины разрешены, поэтому подходит блочная (корзинная) сортировка. Корзин столько же, сколько элементов, элемент `v` идёт в корзину `(int)(v * n)`, а `1.0` в последнюю. Каждую корзину сортируем вставками, потом склеиваем по порядку.

```
[0.25, 0.7, 0.1, 0.9] -> [0.1, 0.25, 0.7, 0.9]  OK
[0.05, 0.05, 0.8] -> [0.05, 0.05, 0.8]  OK
```

Сложность: в среднем O(n), потому что при равномерном распределении в корзину попадает O(1) элементов. Худший случай O(n²), когда всё попало в одну корзину. Память O(n).

## 2. Коды товаров — RadixSort

Сортировку подсчётом по самому коду делать нельзя: понадобился бы массив счётчиков на 10¹² ячеек. Поэтому LSD-поразрядная сортировка: 12 проходов, по одному на каждую десятичную цифру, начиная с младшей. Внутри прохода устойчивая сортировка подсчётом, у которой всего 10 счётчиков. Коды хранятся в `long`, потому что 12 цифр в `int` не помещаются.

```
[123456789012, 12, 900000000000] -> [12, 123456789012, 900000000000]  OK
[111111111111, 101010101010] -> [101010101010, 111111111111]  OK
```

Сложность: O(d·(n + k)) при d = 12 и k = 10, то есть O(n). Память O(n + k).

## 3. Результаты бросков — CountingSort

Значений всего шесть (1..6), поэтому сортировка подсчётом: считаем, сколько раз выпало каждое число, и выписываем их по возрастанию. Тот же массив счётчиков сразу даёт повторы.

```
[6, 1, 6, 3, 2] -> [1, 2, 3, 6, 6]  OK
  повторы: 6 x2
[4, 4, 2, 5] -> [2, 4, 4, 5]  OK
  повторы: 4 x2
```

Сложность: O(n + k) при k = 6, то есть O(n). Дополнительная память O(k).
